# Apex Content Backlog — future original resources

Prioritized backlog for NEW resources. Do **not** auto-generate these — each
needs real, original Apex data (measurements, tests, photos) so it earns its
place. No fabricated statistics, test results, or customer data. Build only when
the "Original evidence needed" column can be satisfied truthfully.

| Priority | Resource | Target query | Intent | Recommended URL | Content angle | Original evidence needed | Supporting products | Internal links | Cannibalization risk |
|---|---|---|---|---|---|---|---|---|---|
| 1 | **Product weight & setup database** | "trade show display weight", "how long to set up a canopy tent" | Commercial / research | `/resources/product-weight-and-setup` | A single table of packed weight, packed dimensions, setup time and people-required per SKU | Real measured weights + timed setups per product | All products | Every product page (spec block), size guides | Low — data hub, not a keyword page |

## Notes
- Items 3, 4, 5 are **owner-evidence-gated** (real transit data, real tests, real
  videos). Ship the structure only when the evidence exists.
- Items 1, 2, 6 can be built from data already in the repo (weights TBD for #1).
- Keep each new URL to a distinct intent to avoid cannibalizing existing pages
  (see the risk column) — the same discipline used across `/products`,
  `/trade-show-displays` and the category pages.
